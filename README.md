# 面试问答助手（InterviewQA）

录制**电脑正在播放的声音**或**麦克风** → 边录边转文字 → DeepSeek 结合你的简历，给出约 200 字、可口头作答的面试参考答案 → 聊天形式流式显示。也支持直接手动输入问题。

应用不自带模型额度，需要填写你自己的 API Key；密钥只保存在本机，不会上传到任何第三方。

## 快速开始

```bash
npm install
npm start
```

首次启动会弹出初始化引导，分三步完成：

1. **模型服务**：填 DeepSeek 与 MiMo ASR 的 API Key，点「测试连接与转写」当场验证两条链路；
2. **个人简历**：选择 PDF / TXT / MD 简历文件（可多选，也可暂时跳过）；
3. **录音与识别**：选声音来源（电脑声音 / 麦克风）、选麦克风设备，点「测试录音」确认真的能收到声音。

三步走完才会进入使用界面。之后任何时候都能从右上角齿轮图标打开设置面板修改。

也可以完全用环境变量注入，跳过填 Key 这一步：

```bash
DEEPSEEK_API_KEY=sk-xxx MIMO_API_KEY=sk-yyy npm start
```

> `config.json` 与 `resume/` 下的个人材料都在 `.gitignore` 中排除，**不会进仓库**；打包时也不会进安装包。

## 平台差异

| 能力 | Windows | macOS |
| --- | --- | --- |
| 录制电脑声音 | WASAPI 回环，开箱可用 | 需 macOS 13+ 并授予「屏幕录制」权限 |
| 录制麦克风 | 首次使用时由系统询问授权 | 首次使用时弹出系统授权框，需在「隐私与安全性 → 麦克风」中允许 |
| 手动输入提问 | 可用 | 可用 |

**macOS 首次使用**：点「开始录音」时系统会弹出屏幕录制授权，勾选本应用后**需要重新打开应用**才生效。若误点了拒绝，到「系统设置 → 隐私与安全性 → 屏幕录制」里勾选回来即可；应用内的提示条上也有直达按钮。

## 使用方式

1. 在底部选择声音来源：**电脑声音**（面试官外放）或**麦克风**（自己出声），选麦克风时可指定具体设备；
2. 打开面试视频 / 音频并开始播放，或直接对着麦克风说话；
3. 点底部「开始录音」，无需虚拟声卡；
4. 录音过程中已识别的文字实时出现；
5. 点「结束这一段」，约 1 至 2 秒后补全最后一句，随即由 DeepSeek 流式生成回答（适合分点的问题会自动用 1. 2. 3. 分点作答）；
6. 生成中按钮变为「停止回答」，点击可随时中断，已生成内容保留；
7. 也可以忽略录音，直接在底部输入框打字提问（回车发送）。

音源可以随时切换，切换即生效并记住；录音过程中不允许切换，避免录到一半换了设备。

## 设置面板

右上角齿轮图标，分四个页签：

- **模型服务**：DeepSeek / MiMo 的 Key、接口地址、模型名，两条链路各有独立的测试按钮；
- **回答与识别**：声音来源与麦克风设备、录音测试、回答字数上限、携带历史轮数、思考深度、简历注入策略、切片参数；
- **简历材料**：添加 / 移除简历文件、强制重新解析、打开材料目录；
- **关于**：版本、平台、语音识别方式、当前声音来源、配置文件与简历目录位置。

配置落在系统用户目录，界面里可以直接打开：

- Windows：`%APPDATA%\InterviewQA\config.json`
- macOS：`~/Library/Application Support/InterviewQA/config.json`

密钥在界面里只回显尾部四位，完整值不会回传到渲染层。

## 连接与录音自检

自检分三块，引导与设置里都能跑，结论的措辞完全一致：

| 检查项 | 做法 | 能验出什么 |
| --- | --- | --- |
| DeepSeek 作答 | 打一次 `/models`，不消耗 token | Key 是否有效、接口地址对不对、网络是否可达 |
| MiMo 转写 | 用一段测试音频走一次真实转写 | Key、接口地址、模型名、网络四项一并验到 |
| 录音 | 按当前音源打开 2 秒，读取电平峰值 | 设备能否打开、权限是否就绪、到底有没有收到声音 |

转写自检会真的送一段音频过去，而不是只打一个接口：接口能通不等于模型名写对了，也不等于账号开通了语音识别，只打接口会让这两类错误留到面试现场才暴露。

录音自检的结论分三档——打不开设备、设备正常但 2 秒内没收到声音、收到声音（附峰值电平）。「没声音」不会被笼统地报成「正常」，你能立刻知道该去查什么。

## 基于简历作答

在设置的「简历材料」里添加简历文件（支持 PDF / TXT / MD，可多份并存）：

- **首次解析**：提取文字 → 调 DeepSeek 整理成结构化背景档案 → 缓存下来；
- **之后启动**：直接复用缓存，不再调用模型；
- **换了文件**：源文件的大小或修改时间变了会自动重新解析；
- **想微调档案**：直接编辑 `profile.md`（源文件不变时不会被覆盖）。

解析期间录音和提问照常可用，首屏约 10 至 15 秒。

### 按问题类型智能注入（默认开启）

不会每次都把整份简历塞给模型，而是先判断问题类型，只注入相关片段：

| 问题类型 | 举例 | 注入内容 |
| --- | --- | --- |
| 技术八股 / 理论题 | 进程和线程的区别？ | **不注入** |
| 项目类 | 你项目里最难的地方是什么？ | 项目经历 + 科研成果 |
| 实习类 | 你在上一家公司具体做了什么？ | 实习经历 + 专业技能 |
| 科研 / 荣誉 / 学业 / 技能 | 你拿过哪些奖项？ | 对应章节 |
| 自我介绍 / 优势 / 动机 | 介绍一下你自己 | 完整档案 |

判定全在本地用关键词完成，不额外调用模型、不增加等待时间。日志里会打印判定结果。

## 配置项

`config.json` 由应用维护，也可以手改（改完重启生效）。文件是增量式的，只需写要改的字段：

| 字段 | 说明 |
| --- | --- |
| `deepseekApiKey` / `deepseekModel` | DeepSeek 的 Key 与模型名 |
| `stt.mimo.apiKey` / `model` / `language` | MiMo ASR 的 Key、模型、语种 |
| `stt.maxConcurrent` | 转写并发数，默认 4 |
| `audio.source` | `system`（电脑声音，默认）或 `microphone`（麦克风） |
| `audio.deviceId` / `deviceLabel` | 选定的麦克风；deviceId 变化时按名称兜底匹配 |
| `chunk.targetSeconds` / `maxSeconds` | 切片目标时长与硬上限，越小越实时 |
| `chunk.silenceThresholdRms` | 静音判定阈值，录不到声音时调小 |
| `resume.enabled` / `contextMode` | 是否启用简历、注入策略（`smart` / `all` / `none`） |
| `answer.maxChars` / `historyTurns` | 回答长度要求与携带的历史轮数 |
| `answer.reasoningEffort` | 作答时的思考深度，默认 `none`（首字更快） |
| `ui.setupDone` | 初始化引导是否已走完 |

## 打包

```bash
npm run build:win  # Windows 安装版 + 免安装版 → dist/*.exe
npm run build:mac  # macOS dmg + zip（arm64 与 x64）→ dist/
```

推到 GitHub 后 `.github/workflows/build.yml` 自动完成多平台构建，打 tag 会额外创建 Release：

```bash
git tag v1.2.0 && git push --tags
```

应用内置自动更新，更新源就是本仓库的 Releases：安装版会在后台下载新版本，重启后完成替换；免安装版只会提示新版本，需要点「打开下载页」自行下载。源码运行不检查更新。

- Node.js 20+

## 常见问题

- **提示没有录到声音**：先确认音源选对了——用电脑声音时要确保电脑确实在播放且未静音，用麦克风时要确认选中的是正在使用的设备；也可以点设置里的「测试录音」看电平有没有读数。
- **麦克风下拉里设备名是空的**：麦克风名称需要先授权才会显示，点一次「测试录音」完成授权即可。
- **切到麦克风后提示设备不可用**：说明保存的设备已被拔掉或更换，应用会自动退回默认设备，再点一次录音即可。
- **macOS 点了录音没反应**：检查「系统设置 → 隐私与安全性 → 屏幕录制」是否勾选了本应用，授权后需要重新打开应用。
- **macOS 录到的是静音**：应用会在开始时校验音频通道，若提示「音频通道没有真正启动」，重启应用后重试；仍未恢复就确认本应用的屏幕录制权限处于勾选状态。
- **测试 MiMo 转写返回 401 / 404**：401 是 Key 无效，404 是接口地址或模型名不对，按提示里的那一行逐项对一遍。
- **回答没有结合简历**：看顶部徽标是否显示简历状态；没有就到设置的「简历材料」里添加文件。
- **简历解析失败**：多半是扫描件（图片型 PDF）提取不到文字，换成文本版 PDF 或直接放 txt/md。
- **回答没生成完就停了**：这是「停止回答」的正常行为，已生成部分会保留。
- **想更长 / 更短的回答**：在设置里改「回答字数上限」，或直接改 `config.json` 的 `answer.maxChars`。
- **检查更新失败**：公司网络若拦截 `github.com`，更新检查会连不上；这种网络环境下只能手动到 Releases 页面下载。
- **免安装版没有自动更新**：这是有意的——单文件形态无法自我替换。改用 `*-win-x64-setup.exe` 安装一次即可获得自动更新，安装时不会动 `%APPDATA%\InterviewQA` 下的配置与简历。
